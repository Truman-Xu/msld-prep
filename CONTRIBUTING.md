# Contributing to msldprep

For everyone who changes this repository, human or AI. AI agents get their working
instructions from [AGENTS.md](AGENTS.md); the rules here bind them too.

## Set up

The development environment is crimm's, `crimm-dev`, which has every dependency of this
project (RDKit, NumPy, PyYAML, crimm, pandas, OpenBabel, pytest):

```bash
conda activate crimm-dev
pip install -e ".[test]" --no-deps
```

crimm supplies the RTF and PRM parsers. The dependency is the latest PyPI release for now;
the version will be pinned once the crimm overhaul is finished. Note that `crimm-dev` itself
carries an editable install of the local crimm checkout, not the PyPI release.

The CGenFF program is not installable from conda. Tests that call it skip themselves, with a
reason, unless you point to it:

```bash
export MSLDPREP_CGENFF_PATH=/export/apps/RockyOS8/cgenff/src/2026_May/silcsbio.2026.1/cgenff/cgenff
export MSLDPREP_CGENFF_BASE_PRM=...   # only if par_all36_cgenff.prm is not next to the program
export MSLDPREP_OBABEL_PATH=/export/apps/RockyOS8/openbabel/3.1.1/bin/obabel   # validation oracle
```

If a variable is unset, `cgenff` or `obabel` on `PATH` is used; failing that, the tests that
need it skip. The command-line tool and `run_msld_prep_from_smiles.py` read the same CGenFF
variables. No install path belongs in source or in example configs. One test also imports the unmodified
legacy `msld_prm.py` from a sibling checkout, `../msld-py-prep`.

## Run the tests

```bash
pytest -q
```

Every bug fix adds a test that fails without it. The standards behind this are in
[docs/dev/BEST_PRACTICES.md](docs/dev/BEST_PRACTICES.md).

## Run the pipeline

Step 1 defines the common core and writes a reviewable checkpoint; step 2 builds the CHARMM
and ALF files from it. Annotated examples are in `configs/`.

```bash
python msld_prep_cli.py from-files --config configs/from_files_example.yaml
python msld_prep_cli.py build --config configs/build_example.yaml
```

## Changing code

- One concern per commit and per pull request. A fix does not ride along with a rename.
- Library code logs or raises; it does not `print`. Raise a subclass of `MsldPrepError`. Do
  not use `assert` to validate input.
- The package attaches only a `NullHandler`. Configure logging in the application, not in
  `msldprep`.
- Say in a docstring whether a function modifies its argument, and give units for any
  physical quantity (Å, e).
- `msldprep/sybyl_typing_data.py` is generated by `scripts/generate_sybyl_typing_data.py`
  from `data/atomtyp.txt` and `data/types.txt`. Regenerate it; do not edit it.
- A change to any file the pipeline writes is a change to a contract with CHARMM and the
  downstream scripts. Make it on its own and describe it.
- Run output (`work.*/`, `build.*/`) is git-ignored; do not commit it.
- A `TODO` in code carries an issue number.

## Issues and pull requests

- Work is tracked as GitHub issues at https://github.com/Truman-Xu/msld-prep/issues. Use the issue forms.
- Open a pull request from a short-lived branch. It needs passing tests and a description of
  why the change is made. Squash-merge; delete the branch after.
- A correctness bug (wrong charges, core, parameters or topology in the output) blocks use of
  the affected release.

## Credit and authorship

- Every commit carries its authors. An AI model that wrote a substantial part signs with a
  trailer naming the exact model: `Co-Authored-By: <model name and version> <vendor
  no-reply address>`.
- Source files carry no signatures: no author lines, "generated with" banners, model names or
  session notes in code, comments, docstrings or file names. `git log` and `git blame` are
  the record.
- Do not sign for code ported or derived from another project as if it were original. The
  pipeline replaces `msld-py-prep`; keep that project's credit where its logic was carried over.
- Never remove or rewrite someone else's credit.
